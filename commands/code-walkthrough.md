## 任务

对 `$ARGUMENTS` 描述的功能或模块，生成一份完整的 **code walkthrough**：从外部输入进入系统开始，沿着实际执行路径，逐步讲解每个关键函数/文件的作用，直到处理完成返回结果。

## Workflow

### Step 1: 确定入口和出口

- 找到该功能的 **入口点**（用户调用/事件触发/消息到达的第一行代码）
- 找到该功能的 **出口点**（最终返回/事件发出/副作用生效的位置）
- 如果不明确，先用 grep/find 搜索关键词，定位核心文件

### Step 2: 追踪执行路径

从入口开始，按实际运行时的调用顺序，逐层深入：
- 每到一个关键函数，记录：文件路径、行号、函数签名
- 重点关注：数据如何变换、控制流如何分支、异步边界在哪里
- 遇到循环/事件循环时，标明循环体和退出条件
- 遇到 spawn/channel/callback 等异步分叉时，标明新的执行线

### Step 3: 先画出调用树总图

在追踪完执行路径后，**立即在文档最顶部**（标题下方）输出完整调用树，然后再展开各 Phase 细节：
- 缩进表示调用深度
- 每行标注函数名和文件位置（`[file:行号]`）
- 在异步分叉点（线程/协程/callback）用注释标注

### Step 4: 组织为 Phase

将执行路径按逻辑阶段划分为多个 Phase，每个 Phase：
- 有一个清晰的标题（描述这一阶段做什么）
- 包含精简的代码片段（只保留核心逻辑，删掉错误处理/日志/不相关分支）
- 代码片段中用中文注释标注关键行的作用
- 标注文件路径和行号

### Step 5: 画出调用栈总图（结尾重复一次）

在文档最后再重复一次完整调用栈，方便对照 Phase 细节后回顾全貌。

### Step 5: 补充机制细节（可选）

如果功能涉及特殊机制（如消息队列、限流、状态机），单独用小节讲解其内部实现。

## 输出格式

```markdown
# [功能名] Code Walkthrough

从 [入口描述] 到 [出口描述] 的完整执行路径。
所有文件路径相对于 [项目根目录]。

## 要求

- 全程使用中文讲解，代码保持原文
- 代码片段只保留 **理解执行路径所必需的行**，大胆删减（错误处理、日志、metrics、不相关分支全删）
- 每个代码片段不超过 20 行，超过就拆分为子步骤
- 精简代码中用 `// ←` 或 `// ↑` 注释指向关键点
- 确保标注的行号是准确的（先 Read 确认再写）
- Phase 之间用 `---` 分隔，保持视觉清晰
- **调用树必须出现两次**：文档顶部（总览）和文档底部（回顾），内容完全一致
- 调用栈总图必须覆盖所有 Phase 中提到的函数
- 如果功能太大（超过 10 个 Phase），先给出概览再问用户要深入哪部分
